# 챕터 생성 운영

Supabase SQL Editor에서 `supabase/migrations/20261031_catalog_generation.sql`, `20261031_publish_chapter.sql`을 순서대로 적용한다. 새 테이블은 서비스 역할만 접근하고, 사용자 API는 Malo 인증의 프로필 ID로 소유권을 제한한다.

`MALO_DATA_MODE=supabase`를 설정한 운영 환경에서 `node --env-file=.env --import tsx scripts/seed-catalog.ts --generate`를 실행하면 FE PR7 원본 카탈로그와 여자친구·교수 교육과정 8개 챕터의 생성 예약을 저장한다. 챕터당 4개, 총 32개 서브 챕터이며 각각 8개 학습자 발화가 있다. 이미지의 CH N은 순서 4, 표시 이름 CH N으로 보존했다. 제공되지 않은 중간 챕터는 만들지 않았다. 배포 이미지에는 tsx가 없으므로 초기 seed는 개발 체크아웃에서 수행한다.

초기 기본 교육과정은 calm 성격이다. 기존 FE 대본은 각 3개 성격으로 보존했고, 개인 생성은 선택한 성격을 생성 프롬프트에 고정한다. 예시로 그려진 A등급·완료 상태는 학습 기록에 넣지 않는다. 대본이 없는 옛 예시 카드에는 unavailable을 표시한다.

VM에 `ops/malo-generation-worker.py`를 `/usr/local/sbin/`, service/timer를 `/etc/systemd/system/`에 설치한다. `systemctl enable --now malo-generation.timer`로 앱 없이 실행된다. 토큰은 기존 BE 컨테이너 환경에서만 읽으며 명령 인수에 넣지 않는다. 워커는 원자적으로 작업 1개를 가져와 한 단계만 진행하고, 결과를 체크포인트에 저장한 후 재예약한다. 프로세스 중단은 5분 lease 만료 후 회복하며 같은 단계 실패는 2회로 제한한다. 완료 저장은 프로필 이관과 충돌하지 않도록 DB 함수로 현재 소유자에게 원자적으로 게시한다.

단계는 outline → lesson 1..N → background → publish다. Lablup이 구성되면 LLM은 우선 사용하고, 실패 시 OpenAI로 전환한다. 실패를 mock 응답으로 바꾸지 않는다. 입력·생성물은 무료 moderation API로 검사하며 검사 실패 시 게시하지 않는다. 욕설·성적·공격적 내용을 피하고 상대의 거절·유보·동의를 존중하도록 교육용 프롬프트를 고정한다. 모델 안전성 검사는 완전한 보증이 아니므로 기본 교육과정은 실제 대본도 검토한다.

각 회차는 8개 순차 beat, 세 번째 발화 후 direct/considerate 두 경로, 4~6번째 대사 변형, 7번째에서 합류한다. happy/deferred/breakdown 결말을 분리하며 서버가 체력·진행·보상을 결정한다. 모델은 허용된 경로·결말 ID만 선택한다. O 판정과 이야기상 요청 수락은 별개다.

배경은 기존 카페·거리·사무실, 사전 생성한 대학 공용실·공부 책상을 우선 재사용한다. 새 장면만 이미지 API를 호출하고 캐시한다. 이미지 호출의 기존 일일 한도 20회·예산 $2를 올리지 않았다. 초기 두 배경은 ChatGPT 내장 이미지 생성 도구로 제작해 저장했다. 일반 개인 생성에서 이미지 한도를 넘으면 해당 job이 failed로 표시되며 다른 학습에는 영향이 없다.

웹 푸시는 BE 환경에 `MALO_VAPID_PUBLIC_KEY`, `MALO_VAPID_PRIVATE_KEY`, `MALO_VAPID_SUBJECT`를 설정한다. 공개키만 FE에 반환한다. 알림에는 개인 대사나 시나리오를 넣지 않는다. 만료 구독(404/410)은 제거하고, 알림 오류는 이미 준비된 챕터를 실패로 되돌리지 않는다. 실제 브라우저의 SW·권한·홈 화면 설치는 FE 구현과 기기 테스트가 필요하다.

녹음 중 전사를 위한 `/speech/realtime-session`은 gpt-live-transcribe용 60초 임시 자격증명을 반환한다. 만료는 새 연결을 시작할 수 있는 기간이며 이미 시작한 연결의 사용시간 상한은 아니다. FE가 녹음·연결을 닫고, 서버의 일일 세션 발급 한도를 유지한다. STT 전사에는 측정되지 않은 음성 감정·발음 점수를 만들지 않는다. 녹음 종료부터 3~5초는 목표이며 기기별 종단 실측이 필요하다.

검증: BE는 소유권·게스트 이관·중복 생성·단계 재개·게시 전 비공개·실시간 분기·정확히 한 번 보상과 기존 학습 흐름을 테스트한다. AI는 분기 그래프 검증·안전성 검사 실패·회차 수 검증·기존 음성/평가 계약을 테스트한다. FE 작업 목록은 frontend의 `docs/FE_INTEGRATION.md`를 따른다.
