# 상황 안내 · 학습 판정 · 완료 보고서

프런트 앱 소스 변경 없이 BE/AI에 제공하는 계약이다. 전체 스키마는 `docs/openapi.json`을 따른다.

## 진입

`POST /api/v1/sessions`에 `sceneId`, `aiMode: "live"`, `subtitleLanguage: "en"`을 전달한다. 응답의 `briefing`에는 제목·상대·짧은 상황·목표와 선택 언어 번역이 있다. 답안이나 속마음은 포함하지 않는다. FE는 이를 읽은 뒤 시작하도록 구현한다.

## 판정

`turn.evaluation.mark`는 `O | △ | X | ?`다. O는 매우 적절하며 사소한 오류를 허용한다. △는 의사소통은 되지만 표현·뉘앙스 보완이 필요하다. X는 핵심 의도의 명백한 오해·심한 무례다. ?는 의미를 판단하기 어렵거나 화제와 무관한 응답이다. 음성 인식 오류가 의심되면 확인을 요청하고 차감하지 않는다.

`reason`, `reasonSubtitle`, `goalAchieved`, `progression`을 함께 제공한다. 목표를 달성한 △도 다음 대사로 진행한다. X는 신뢰도 0.75 이상에서만 체력을 차감한다. 낮은 신뢰도의 X는 ?로 보류한다. 모국어 답변은 한국어 표현을 제안하고 재도전하며 차감하지 않는다.

판정과 `turn.emotion`·`render`는 독립적이다. 정중한 거절은 O이면서 캐릭터가 서운해할 수 있다. 기존 reaction 기록은 표시 코드만 변환하고 기존 점수·사유를 재판정하지 않는다. 정책 버전은 `judgment-v2-draft`다. 사용자가 제공한 학습 흐름을 반영했으며 세부 경계 사례·점수 가중치는 임시다.

## 보고서

실시간 학습 완료 시 상세 보고서 작업을 자동 등록한다. 종합 결과는 즉시 반환하고 `result.report`로 작업 ID·상태를 알린다. 보고서 실패가 이미 끝난 학습이나 코인 지급을 취소하지 않는다.

| API | 동작 |
|---|---|
| `GET /sessions/{id}/report` | 본인 보고서 상태 조회. 새 유료 생성을 시작하지 않음 |
| `POST /sessions/{id}/report` + `{}` | 완료된 세션 보고서 생성·기존 작업 재사용 |
| `POST /sessions/{id}/report/retry` + `{}` | 실패 작업 재시도 |

상태는 `queued`, `running`, `ready`, `failed`. 진행 중 세션은 409, 요청한 적 없는 보고서는 404다. 큐는 Supabase에 저장하므로 화면을 닫아도 계속 처리한다. 같은 세션을 재조회해도 보고서·보상을 중복 생성하지 않는다. 게스트에서 회원으로 이관할 때 소유권도 이동한다.

`report.overview`에는 기존 점수·등급·성취 지표·소요 시간·발화 수·`judgmentCounts`가 있다. `summary`는 선택 언어로 종합 의견·강점·보완·문화적 학습점·다음 연습을 제공한다. `details`는 모든 실제 시도에 대해 대사·답변·기존 판정·NPC의 설정된 의도·비언어 단서·문화적 설명·피드백·칭찬 또는 대안·최초 답변 비교를 제공한다. 잘한 답의 `alternativeExpression`은 null이다. 과거 판정이 없는 기록은 임의 판정 없이 legacy로 표시한다.

이는 연습 지표다. 공인 숙련도나 실제 사용자의 심리 상태를 추정하지 않는다. 보고서 AI는 기존 발화의 점수와 판정을 바꾸지 않는다.

## 운영

배포 전 `supabase/migrations/20261101_learning_reports.sql`을 적용한다. 기존 `malo-generation.timer`가 챕터·보고서 작업을 처리한다. API 키는 서버에만 저장한다. Web Push는 구독이 있는 사용자에게 완료 시 전송하며, FE의 서비스 워커·알림 권한 구현이 필요하다.
